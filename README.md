# CrimeVault

CrimeVault is an academic crime investigation and case management prototype. The current checked-in implementation is a Java 17 / Spring Boot API with JDBC access to Oracle and a static HTML, CSS, and JavaScript frontend.

## Current implementation status

The backend contains API modules for cases, people, investigators, case-person links, and investigator assignments. Those five frontend areas use the existing backend routes and show loading/error states. Person IDs are generated by the database, and case-specific roles are saved on the case-person relationship. Evidence, custody, interviews, forensic records, and timelines do not have checked-in Oracle-backed implementations and remain demo-only where shown.

See [docs/implementation-status.md](docs/implementation-status.md) for the audit checklist, verification evidence, and blockers. The finalized 11-relation schema could not be checked against this repository because no schema DDL, migration, or ER model is checked in. Do not infer that the existing DAO SQL validates the approved model. Frontend-to-Oracle operations have not been verified in this environment.

## Prerequisites

- JDK 17 or later compatible with the configured Spring Boot build.
- Oracle Database and the approved CrimeVault schema.
- `CRIMEVAULT_DB_USER` and `CRIMEVAULT_DB_PASSWORD` set in the shell running the backend.
- A static file server for `frontend/` (the existing CORS configuration allows `localhost:5500` and `127.0.0.1:5500`).

Credentials must remain in environment variables and must not be committed.

## Run the backend

From `backend/`, set the two environment variables in PowerShell, then run:

```powershell
$env:CRIMEVAULT_DB_USER = 'your_schema_user'
$env:CRIMEVAULT_DB_PASSWORD = 'your_schema_password'
./mvnw.cmd spring-boot:run
```

The configured Oracle URL is `jdbc:oracle:thin:@//localhost:1521/FREEPDB1`. Confirm that this matches your local Oracle service before starting the application. The application needs a working database connection at startup.

## Run the frontend

Serve the `frontend/` directory on port 5500 using your preferred local static server, then open `http://localhost:5500`. The API helper targets `http://localhost:8080/api`. Cases, People, Investigators, Assignments, and Case–Person screens use backend records and report load/save errors. Evidence and custody remain demo-only and explicitly state that their actions are not persisted.

## API routes currently present

| Module | Routes |
|---|---|
| Cases | `GET /api/cases`, `GET /api/cases/{id}`, `POST /api/cases`, `PUT /api/cases/{id}` |
| People | `GET /api/people`, `GET /api/people/{id}`, `POST /api/people`, `PUT /api/people/{id}` |
| Investigators | `GET /api/investigators`, `GET /api/investigators/{id}`, `POST /api/investigators`, `PUT /api/investigators/{id}` |
| Case-person | `GET /api/case-people`, `GET /api/case-people/case/{caseId}`, `POST /api/case-people` |
| Assignments | `GET /api/assignments`, `GET /api/assignments/{id}`, `POST /api/assignments`, `PUT /api/assignments/{id}` |
| Health | `GET /api/health` |

Route presence is not evidence of schema compatibility or live Oracle verification. There are no DELETE routes in these modules; historical records should not be deleted without an approved retention rule.

## Tests

From `backend/`, run:

```powershell
./mvnw.cmd clean test
```

This test suite currently uses Spring context and mocked DAO tests. These tests do not prove that Oracle is available or that the queries match the configured database schema. See the implementation status document for the latest observed results.
